# feedctl

`feedctl` is a `gh`-style CLI over the Feedless HTTP API (`/api/v1`), written in Go and shipped as a single static binary.

Its HTTP client (`internal/api/client.gen.go`) is generated by [oapi-codegen](https://github.com/oapi-codegen/oapi-codegen) from `packages/http-api/src/main/resources/openapi/openapi.yaml`, the contract owned by `packages/http-api`. Never hand-edit that file — regenerate it (see Generating the API client below).

## Usage

### Install

Each instance serves the `feedctl` build that matches its API (see The binaries each self-hosted instance serves below). Install it from the instance you want to use:

```
curl -fsSL https://<instance>/cli/install.sh | sh
```

The binary goes to `~/.local/bin`; pass `-s -- --dir <path>` to install elsewhere. A `feedctl` whose version differs from the instance's prints a warning on every call.

### Check the instance

`feedctl status` needs no login: it reports a host's version, build and number of connected prerender agents (`--host <host or URL>`, else the default or only configured host; `--json`/`--jq` for the raw response), and exits 1 when the host is unreachable, answers an error, or has no agent connected.

```
feedctl status --host https://<instance>
```

### Log in

Create an API token in the instance's web UI: on the security page of your profile, give it a name (e.g. `laptop`) and copy the value, which is shown only once. Tokens created before tokens had names are rejected; create a new one. Then:

```
feedctl auth login --url https://<instance>
```

`--url` is the host that serves `/api/v1`, which is not always the web frontend's host. The command prompts for the token; `--with-token` reads it from stdin instead (`echo "$TOKEN" | feedctl auth login --url … --with-token`). The token is verified before anything is stored, and kept in the OS keyring, or in `hosts.yml` only when no keyring exists. The first host you log in to becomes the default.

`feedctl auth status` shows every configured host and whether its token still works. `feedctl auth logout` logs out of the host that `--host`, `FEEDCTL_HOST` or the default resolves to; if that was the default, another configured host becomes the default.

### Commands

`auth` (`login`, `status`, `logout`), `api`, `repo`, `record`, `source` (including `source run`), `harvest`, and `status`; `feedctl <command> --help` lists each one's subcommands and flags.

```
feedctl repo list --search events
feedctl source list -R <repo> --errored          # sources with at least one consecutive error, most broken first
feedctl source view <source> -R <repo>           # the flow as a numbered action list
feedctl source run <source> -R <repo> --dry-run  # scrape without importing records or touching the source
feedctl harvest list -R <repo> -S <source>
feedctl harvest view <harvest> -R <repo> -S <source> --log
feedctl api user                                 # any request; the path is relative to /api/v1
```

`source run` waits for the harvest to finish; `--no-wait` prints the queued harvest id and exits. `--dry-run --flow <file>` tests an edited ScrapeFlow JSON without saving it. Running a source needs a prerender agent connected to the instance.

List and view commands print a table by default; `--json [fields]` prints JSON, and `--jq <expr>` filters it.

### Configuration

| Setting | Source, in order of precedence |
|---|---|
| Host | `--host` › `FEEDCTL_HOST` › the default host in `hosts.yml` |
| Token | `FEEDCTL_TOKEN` (applies to the targeted host only) › OS keyring › `hosts.yml` |
| Repository | `-R`/`--repo` › `FEEDCTL_REPO` |

`hosts.yml` lives in `$XDG_CONFIG_HOME/feedctl/`, else `~/.config/feedctl/`.

### Exit codes

| Code | Meaning |
|---|---|
| 0 | Success |
| 1 | Any other error, including an unknown flag, an unreachable host and `status` with no agent connected |
| 2 | Cancelled (Ctrl-C, aborted edit), or an invalid `--host` for `status` |
| 4 | Not logged in, or the token was rejected |

## Layout

- `cmd/feedctl/main.go` — entry point; embeds the build version via `-ldflags`.
- `internal/cmd/` — the Cobra command tree, starting at `NewRootCmd`.
- `internal/api/` — the generated API client (`client.gen.go`), its oapi-codegen config (`cfg.yaml`), and the `go:generate` directive (`generate.go`).

## Prerequisites

Go 1.27 (the pinned toolchain is 1.27.1 — `go` picks it up automatically via `go.mod`). `oapi-codegen` and `golangci-lint` are not installed globally; both are pinned as Go tool dependencies in `go.mod` and run via `go tool <name>`, so no separate install step is needed.

## Building and testing

All of this is also wired into Gradle (`packages/cli/build.gradle.kts`), so `./gradlew :packages:cli:lint`, `./gradlew :packages:cli:test`, and `./gradlew :packages:cli:build` work from the repo root exactly like the other modules' `lint`/`test`/`build`.

Direct Go commands, run from `packages/cli`:

```
go vet ./...
go tool golangci-lint run ./...
go test ./...
go build -ldflags "-X main.version=<version>" -o build/feedctl ./cmd/feedctl
```

`build/feedctl --version` prints `feedctl version <version>`.

## Generating the API client

Run `go generate ./...` after `openapi.yaml` changes, then commit the regenerated `internal/api/client.gen.go`. `./gradlew :packages:cli:lint` runs the same regeneration and fails the build if the checked-in client drifted from the spec, so a spec change without a matching regeneration is caught in CI, not by users of the CLI.

Every Go task in Gradle (`lint`'s checks, `test`, `build`, `e2eTest`) first runs `./gradlew :packages:cli:checkGo`. It reads the required version from `go.mod` (the `toolchain` line, else the `go` line), asks `go env GOVERSION` which toolchain `go` actually selects in this module, and fails with a clear message when `go` is not on PATH or the selected toolchain is older — for example because `GOTOOLCHAIN=local` stops `go` from downloading the pinned one. Any Go ≥ 1.21 passes with the default `GOTOOLCHAIN=auto`, since it downloads the pinned toolchain itself.

## The binaries each self-hosted instance serves

Feedless is self-hosted, and instances run different versions, so each instance serves the `feedctl` build that matches its own API instead of a single downloadable release. The `server-core` image builds those binaries itself: the first stage of `packages/server-core/Dockerfile` is a Go stage (`golang:1.27.1-alpine`, which must match the `toolchain` line in `go.mod`) that reads this directory as the BuildKit named build context `cli` and puts into the image's `static/cli/`, served under `/cli/**`:

- `feedctl-darwin-amd64`, `feedctl-darwin-arm64`, `feedctl-linux-amd64`, `feedctl-linux-arm64` — statically linked (`CGO_ENABLED=0`), stripped (`-trimpath -ldflags "-s -w"`) binaries whose `main.version` is the image's `APP_VERSION` build argument (`dev` if unset). No Windows build (out of scope for now).
- `SHA256SUMS` — `sha256sum`-format checksums of the four binaries (`shasum -a 256 -c SHA256SUMS` verifies them).
- `install.sh` — a copy of this directory's `install.sh`, unmodified; the server templates its `__FEEDCTL_BASE_URL__` placeholder per instance when it serves `/cli/install.sh` (see `CliInstallScriptController` in `packages/server-core`).

The Go stage runs on the build host's own platform (`--platform=$BUILDPLATFORM`) and cross-compiles, so an `amd64` image builds natively on an `arm64` host. Building the image therefore needs Docker with BuildKit, but no local Go. `./gradlew :packages:server-core:buildAmdDockerImage` passes the context as `--build-context cli=<absolute path of packages/cli>`. To build the image by hand, run `./gradlew :packages:server-core:bootJar` and then, from `packages/server-core`:

```
docker build \
  --build-context cli=../cli \
  --build-arg APP_VERSION=1.2.3 \
  --build-arg APP_BUILD_TIMESTAMP=$(date +%s)000 \
  --build-arg APP_GIT_COMMIT=$(git rev-parse --short HEAD) \
  -t feedless:core-local \
  .
```

A relative `--build-context` path is resolved from the current directory, not from the build context. The core only starts when all three build arguments are set. A local `bootRun` has no `static/cli/`, so it 404s on `/cli/**`; it does not fail to start.
