# feedctl

`feedctl` is a `gh`-style CLI over the Feedless HTTP API (`/api/v1`), written in Go and shipped as a single static binary.

Its HTTP client (`internal/api/client.gen.go`) is generated by [oapi-codegen](https://github.com/oapi-codegen/oapi-codegen) from `packages/http-api/src/main/resources/openapi/openapi.yaml`, the contract owned by `packages/http-api`. Never hand-edit that file — regenerate it (see Generating the API client below).

This package currently ships only the root command and `feedctl --version`. `auth`, `api`, `source`, and `harvest` subcommands land in follow-up tasks.

## Layout

- `cmd/feedctl/main.go` — entry point; embeds the build version via `-ldflags`.
- `internal/cmd/` — the Cobra command tree, starting at `NewRootCmd`.
- `internal/api/` — the generated API client (`client.gen.go`), its oapi-codegen config (`cfg.yaml`), and the `go:generate` directive (`generate.go`).

## Prerequisites

Go 1.27 (the pinned toolchain is 1.27.1 — `go` picks it up automatically via `go.mod`). `oapi-codegen` and `golangci-lint` are not installed globally; both are pinned as Go tool dependencies in `go.mod` and run via `go tool <name>`, so no separate install step is needed.

## Building and testing

All of this is also wired into Gradle (`packages/cli/build.gradle.kts`), so `./gradlew :packages:cli:lint`, `./gradlew :packages:cli:test`, and `./gradlew :packages:cli:build` work from the repo root exactly like the other modules' `lint`/`test`/`build`.

Direct Go commands, run from `packages/cli`:

```
go vet ./...
go tool golangci-lint run ./...
go test ./...
go build -ldflags "-X main.version=<version>" -o build/feedctl ./cmd/feedctl
```

`build/feedctl --version` prints `feedctl version <version>`.

## Generating the API client

Run `go generate ./...` after `openapi.yaml` changes, then commit the regenerated `internal/api/client.gen.go`. `./gradlew :packages:cli:lint` runs the same regeneration and fails the build if the checked-in client drifted from the spec, so a spec change without a matching regeneration is caught in CI, not by users of the CLI.
