# HTTP API (`http-api`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Challenge status:** Complete. `server-core` = application + composition; `domain` holds ports/entities; extract into `domain` incrementally per HTTP task. Open: session/JWT/capability wiring for `http-api`.

**Goal:** Ship a versioned REST API under `/api/v1` as Gradle module `packages/http-api` (OpenAPI schema + codegen + controllers), calling domain use-case ports for auth/session and CRUD of repository, source, document, harvest, plan, and group.

**Architecture:** Hexagonal adapters. `http-api` owns OpenAPI, generates Kotlin Spring API interfaces/models, and hosts REST controllers + OpenAPI↔domain mappers. `graphql-api` remains the GraphQL schema/codegen package; GraphQL resolvers in `server-core` map GraphQL DTOs ↔ domain at the adapter edge. **Use cases and domain ports accept and return domain types only** — GraphQL-generated inputs (`RepositoryCreateInput`, `SourceInput`, etc.) must not appear in use-case signatures. Extract use-case interfaces into `packages/domain` (alongside existing repository ports); `server-core` provides implementations. Spring Boot (`server-core`) depends on `http-api` for component scan / autoconfig of controllers. Auth uses `Authentication: Bearer <jwt>` (and optional `TOKEN` cookie) via `JwtRequestFilter`.

**Why not map OpenAPI → GraphQL inputs:** That would cement GraphQL DTO pollution inside the application core. Mapping belongs only in adapter layers (`http-api`, GraphQL resolvers). Domain commands/entities are the shared language.


**Module layering:** `packages/server-core` is the **application module and composition root** (Spring Boot wiring, use-case implementations, GraphQL resolvers as adapters hosted next to composition). `packages/domain` is the pure domain module (entities, repository interfaces, and — once migrated — ports/rules that still wrongly live in `server-core`). `packages/http-api` is a driving adapter: OpenAPI + controllers + mappers; it depends on **domain** (ports/types), not on `server-core` concrete classes. `server-core` depends on `http-api` to pull controllers into the running app.


**Extract strategy:** Move domain-worthy types out of `server-core` **incrementally** — only what the current HTTP entity task needs (repository first, then source, records, …). Do not big-bang migrate all of `server-core`.

**Use-case ports:** Interfaces live in `packages/domain`; implementations stay in `packages/server-core`. `http-api` depends on the interfaces only.

**Known debt:** Much that belongs in `domain` still resides in `server-core`. HTTP work must not cement that. Prefer extracting needed ports/types into `domain` as prerequisites (or Task 0 slices) rather than having `http-api` import `server-core`.

**Capability context for REST:** A servlet/`OncePerRequest` filter (or application `CapabilityContextPort.withCapabilities { }`) establishes coroutine capability context **before** the controller runs, mirroring GraphQL's `injectCapabilitiesFromSecurityContext()`. Controllers assume context is already set.

**Authorization:** Ownership and permission checks live **inside use-case / application ports**, not in HTTP controllers. Controllers map OpenAPI ↔ application/domain types and call ports; they do not call `*Guard` classes. GraphQL resolvers should converge on the same rule when touching those use cases (guards fold into the use case or become private collaborators of the application service).

**Why controllers live in `http-api`:** Keeps the REST adapter cohesive (contract + implementation) and forces a hard dependency on domain ports instead of reaching into `server-core` types. Rejected alternative: controllers in `server-core` mirroring GraphQL resolvers — weaker module boundary and invites leaking GraphQL types into REST mapping.

**Tech Stack:** Kotlin 2.2, Spring Boot 3.4 (MVC with coroutine/`suspend` controller methods — prefer generator `useCoroutines` / reactive options so controllers never call `runBlocking`), OpenAPI 3.0.3, openapi-generator-gradle-plugin 7.14.0, JUnit 5 + MockMvc/WebTestClient + mockito-kotlin. If the generator only emits WebFlux `Mono`/`Flux`, use that return type at the HTTP edge rather than blocking bridges.

## Global Constraints

- Module name / path: `packages/http-api` (include in `settings.gradle.kts` as `packages:http-api`).
- Base path: `/api/v1` (OpenAPI `servers[0].url`).
- Auth header name is `Authentication` (not `Authorization`): `Authentication: Bearer <jwt>`.
- **`POST /auth/login` authenticates any user with a matching secretKey** (not admin-only). Relax the admin check in the shared auth port so GraphQL `authUser` and REST login share this behavior. Rejected alternative: keep admin-only GraphQL and broader REST (dual semantics).
- Controllers live in `packages/http-api` and implement generated `*Api` interfaces; they depend on **use-case ports in `packages/domain`**, not concrete `server-core` classes. Port implementations and composition live in `server-core`.
- Controllers profile: `@Profile("${AppProfiles.<feature>} & ${AppLayer.api}")` — same pattern as GraphQL resolvers.
- Capability context is set by a request filter / `withCapabilities` **before** the controller; controller methods are `suspend` (or `Mono`/`Flux`) — **no `runBlocking`**, and controllers do not manually inject capabilities.
- Spring `@PreAuthorize` may still gate coarse auth at the HTTP edge; **fine-grained ownership** is enforced inside use cases. Annotate mutating controller methods with `@Throttled`.
- GraphQL type `Record` = domain `Document`. REST path and OpenAPI schema use **`/records`** / `Record` (public-API alignment with GraphQL and CLI). Domain type remains `Document` inside ports/mappers.
- **Harvest** and **Plan** have no create/update/delete in the service layer today — REST exposes **read** (+ list) only. Do not invent write APIs. Harvest `logs` are **omitted (or truncated) by default**; pass `includeLogs=true` for full logs.
- **Source** mutations go through domain ports; list/get use `SourceRepository` or a source port method. Expose nested REST under `/repositories/{repositoryId}/sources`.
- **Group** GraphQL only exposes `User.groups`. REST adds list/create/delete group + membership add/remove by extending the group use-case port (domain `GroupRepository` already has `save` / `findAllByOwner` / `findById`).
- **Scrape `flow` is fully typed in OpenAPI** — mirror GraphQL `ScrapeFlow` / `ScrapeAction` (fetch, extract, execute, click, type, waitFor, select, header, purge) so clients get schema validation and typed codegen. Map OpenAPI flow → domain `List<ScrapeAction>` in `http-api` mappers (same destination GraphQL resolvers already use via `SourceInput.toSource()`).
- **Domain purity:** Any use case still accepting GraphQL DTOs must be refactored to domain commands/entities before (or as part of) the REST task that needs it. GraphQL resolvers become the sole owners of GraphQL↔domain mapping for that operation.
- Do not change GraphQL schema behavior for clients; REST is additive. Resolver internals may gain mapping calls when use-case signatures change.
- **HTTP API is authenticated-only:** every `/api/v1/**` route except `POST /auth/login` requires a logged-in user (`user` capability). Do **not** expose or accept anonymous JWTs for REST (no `POST /auth/anonymous` on HTTP API; anonymous tokens from GraphQL must not authorize `/api/v1/**`). Whitelist only `/api/v1/auth/login` in `SecurityConfig`.
- Apply `@Throttled` to **all mutating** `/api/v1/**` endpoints (POST/PATCH/PUT/DELETE), same as GraphQL resolvers. Move or share the annotation + aspect so `http-api` can use it without depending on unrelated `server-core` types (e.g. keep annotation in a small shared package, or advise `org.migor.feedless.http` from the existing aspect).
- Test style: unit tests with mocked domain ports in `packages/http-api` (MockMvc or WebTestClient); assert JSON status + body.
- **Errors:** JSON `ApiError` with required `code`/`message` and optional `corrId` / `path`. For REST, **always generate** `corrId` server-side (ignore client `corrId` header); put it in MDC and on `ApiError`.
- **Creates:** No `Idempotency-Key` in v1 — retries may create duplicates; clients must avoid double-submit or tolerate duplicates. Existing domain uniqueness (e.g. record content hash) applies only where already implemented.
- **Pagination:** Query params `page` (default 0) and `pageSize` (default 20, max 100). List response wrappers include `items` and **`hasMore`** (true when a full page was returned; clients fetch `page+1` until `hasMore` is false). No total count required in v1.
- **Docs:** OpenAPI lives in `packages/http-api/src/main/resources/openapi/openapi.yaml` only — no Swagger UI and no runtime `/openapi` endpoint in the app.
- Commit after each task with conventional messages.

## Scope note (not separate plans)

This is one subsystem (HTTP adapter + domain-port cleanup required to keep use cases pure). Harvest/Plan write gaps remain intentional. Group REST ships full create/list/get/delete + membership (confirmed); GraphQL remains membership-read via `User.groups` only.

**Trade-off accepted:** Fully typing scrape actions duplicates taxonomy across GraphQL schema and OpenAPI. Mitigation: keep field names/enums aligned with `schema.graphqls` and treat GraphQL as the semantic reference when adding a new action type.

**Trade-off accepted:** No in-app Swagger UI — consumers use the repo OpenAPI file / codegen. Keeps runtime surface small.

**Trade-off accepted:** Extracting use-case interfaces and removing GraphQL types from use cases touches GraphQL call sites. Do that incrementally per entity (repository first, then source, document, …) rather than a big-bang rewrite.

@RestController
@Profile("${AppProfiles.repository} & ${AppLayer.api}")
class RepositoryHttpController(
  private val repositoryUseCase: RepositoryUseCasePort,
  private val mapper: HttpRepositoryMapper,
) : RepositoriesApi {

  @PreAuthorize("@capabilityService.hasCapability('user')")
  override suspend fun listRepositories(
    page: Int?,
    pageSize: Int?,
    product: Vertical?,
    visibility: Visibility?,
    q: String?,
  ): ResponseEntity<RepositoryListResponse> =
    withContext(injectCapabilitiesFromSecurityContext()) {
      val pageable = PageRequest.of(page ?: 0, pageSize ?: 20).toPageableRequest()
      val where = RepositoriesFilter(
        product = product?.let {
          VerticalFilter(eq = org.migor.feedless.Vertical.valueOf(it.name))
        },
        visibility = visibility?.let {
          VisibilityFilter(`in` = listOf(EntityVisibility.valueOf(it.name)))
        },
        text = q?.let { FulltextQueryFilter(query = it) },
      )
      val userId = coroutineContext.userId()
      val items = repositoryUseCase.findAllByUserId(pageable, where, userId)
        .map { mapper.toHttp(it, it.ownerId == userId) }
      ResponseEntity.ok(RepositoryListResponse(items = items, hasMore = items.size == (pageSize ?: 20)))
    }

  @PreAuthorize("@capabilityService.hasToken()")
  override suspend fun createRepositories(
    repositoryCreate: List<RepositoryCreate>,
  ): ResponseEntity<List<HttpRepository>> =
    withContext(injectCapabilitiesFromSecurityContext()) {
      val created = repositoryUseCase.create(mapper.toDomainCreates(repositoryCreate))
      val userId = coroutineContext.userId()
      ResponseEntity.status(HttpStatus.CREATED)
        .body(created.map { mapper.toHttp(it, it.ownerId == userId) })
    }

  @PreAuthorize("@capabilityService.hasCapability('user')")
  override suspend fun getRepository(repositoryId: java.util.UUID): ResponseEntity<HttpRepository> =
    withContext(injectCapabilitiesFromSecurityContext()) {
      val repo = repositoryUseCase.findById(RepositoryId(repositoryId.toString()))
        ?: throw NotFoundException("repository not found")
      val userId = coroutineContext.userId()
      ResponseEntity.ok(mapper.toHttp(repo, repo.ownerId == userId))
    }

  @PreAuthorize("@capabilityService.hasCapability('user')")
  override suspend fun updateRepository(
    repositoryId: java.util.UUID,
    repositoryUpdate: RepositoryUpdate,
  ): ResponseEntity<Unit> =
    withContext(injectCapabilitiesFromSecurityContext()) {
      repositoryUseCase.updateRepository(
        RepositoryId(repositoryId.toString()),
        mapper.toDomainUpdate(repositoryUpdate),
      )
      ResponseEntity.noContent().build()
    }

  @PreAuthorize("@capabilityService.hasCapability('user')")
  override suspend fun deleteRepository(repositoryId: java.util.UUID): ResponseEntity<Unit> =
    withContext(injectCapabilitiesFromSecurityContext()) {
      repositoryUseCase.delete(RepositoryId(repositoryId.toString()))
      ResponseEntity.noContent().build()
    }

  @PreAuthorize("@capabilityService.hasCapability('user')")
  override suspend fun countRepositories(product: Vertical): ResponseEntity<CountResponse> =
    withContext(injectCapabilitiesFromSecurityContext()) {
      val count = repositoryUseCase.countAll(
        coroutineContext.userId(),
        org.migor.feedless.Vertical.valueOf(product.name),
      )
      ResponseEntity.ok(CountResponse(count = count))
    }
}
